# 板块八 相关研究工作

所属：板块八 · 世界坐标系下的三维重建与视图合成（探索性） ｜ 返回总览：[PlanOutline.md](../PlanOutline.md)

本文按特点把与板块八相关的研究工作分成八类，每类说明要解决的问题、核心做法、局限，以及与“直接在世界坐标系生成结果”的关系，供不熟悉三维重建领域的读者先建立整体图景，再读 [8-1](8-1_前馈式大范围重建的坐标策略与块拼接基准.md)。

## 0. 先认识几个术语

| 术语 | 含义 |
| --- | --- |
| 位姿 | 拍摄每张照片时相机的位置与朝向（外参）；相机自身的焦距、主点等称内参 |
| 运动恢复结构（SfM） | 从一组无序照片中同时恢复相机位姿与稀疏三维点 |
| 多视图立体（MVS） | 已知位姿后，从多张照片恢复稠密的三维形状（深度图或点云） |
| 新视角合成（NVS） | 给定若干照片，渲染从没拍过的视角下的画面 |
| 逐场景优化 | 对每个场景单独训练一个模型（如 NeRF），训练要几分钟到几小时 |
| 前馈式 | 模型事先在大量场景上训练好，对新场景只需一次前向推理，不再逐场景训练 |
| 局部坐标系与尺度不确定 | 仅凭照片恢复的结构，只确定到相似变换（旋转、平移与一个整体缩放，共 7 个自由度）；因此输出落在任意的局部坐标系、任意尺度，要变到世界系须另有 GNSS、控制点等信息（通行做法） |
| 度量（metric） | 结果的长度单位是真实的米，而不是相对尺度 |
| RPC | 有理多项式相机模型，卫星影像常随影像附带，直接把地理坐标（经度、纬度、高度）映射到像素；因此卫星影像天然带有地理参考 |

## 1. 经典管线：SfM 加 MVS

**要解决的问题**：从一组无序照片得到相机位姿与三维几何。这是后面所有方法的“输入来源”（第 2、3 类）和“对照对象”（第 4 类），所以先把它的流程与局限讲清楚。读法：读 COLMAP 两篇论文的方法部分 [^1][^2]。

### 1.1 SfM：增量式运动恢复结构 [^1]

流程分两大阶段：

| 阶段 | 步骤 | 做什么 |
| --- | --- | --- |
| 对应搜索 | 特征提取 | 每张照片检测局部特征（位置加外观描述子），要求对光照与几何变化有不变性；SIFT 及其衍生是鲁棒性的“金标准” |
| | 匹配 | 找出哪些照片看到同一块场景；朴素做法对每一对照片比较所有特征，复杂度 $O(N_I^2 N_F^2)$，大规模时不可行，故有各种可扩展匹配策略 |
| | 几何验证 | 对候选照片对用几何模型（基础矩阵、本质矩阵、单应）验证匹配；论文新增“多模型验证”，给场景图标注每一对的模型类型（一般、全景、平面），并检测把不同地标错误连起来的对（论文称“WTF”对）；输出是“场景图” |
| 增量重建 | 初始化 | 从场景图里挑一对精选的两视图重建作为种子 |
| | 图像配准 | 逐张加入新照片，估计其位姿（已知三维点与二维观测对应，即 PnP） |
| | 三角化 | 把新观测到的点恢复成三维点 |
| | 光束法平差（BA） | 对相机参数与点参数联合最小化重投影误差 $E=\sum_j\rho_j(\lVert\pi(P_c,X_k)-x_j\rVert^2)$，用 Levenberg-Marquardt 求解，并利用稀疏结构的 Schur 补加速 |
| | 外点过滤 | 删除误差大的观测与点 |

论文的主要改进：场景图增强（上面的多模型验证）、**下一最佳视图选择**（优先加入能使重建最稳的下一张照片）、更稳健的三角化、迭代式的 BA 加再三角化加外点过滤以减轻漂移、以及对稠密照片集的冗余视图挖掘。论文指出：不做精化，SfM 通常会很快漂移到不可恢复的状态。

**局限与关系**：
- 本文所读论文**没有专门讨论尺度与坐标系的不确定性**；“SfM 只确定到相似变换”（旋转、平移与一个整体缩放，7 个自由度）是视觉几何的通行认识，本文沿用但未在文献中核对。
- 输出的相机位姿在任意的局部坐标系里，因此后文的逐场景方法几乎都继承这一点。
- 增量式流程要反复做 BA，规模大时慢，这正是前馈方法（第 4 类）想绕过的成本。

### 1.2 MVS：逐像素视图选择的深度与法向估计 [^2]

SfM 给出稀疏点和位姿后，MVS 估计稠密几何。论文给出的核心做法：

- **联合估计深度与法向**：用改进的 PatchMatch 采样（随机初始化加传播）为每个像素同时估计深度与表面法向，而不是只估计深度。
- **逐像素视图选择**：不是对所有邻近视图一视同仁，而是为每个像素选出对它有用的视图，选择依据包括三角化角度、入射角与图像分辨率等几何先验，再加一个“时间”平滑项，让相邻像素的视图选择一致。
- **自适应窗口**：用双边的光度一致性，在遮挡边界处表现更好。
- **多视图几何一致性**：把几何一致性项并入估计，使深度与法向的精化与基于图像的融合同时进行。
- **过滤与融合**：可靠地过滤并融合深度与法向图，得到无外点的点云，进而可直接成网格。

**局限与关系**：MVS 以已知位姿为前提，位姿误差会直接传进几何；输出是点云或网格，没有可用于新视角渲染的外观模型，这正是下一类（神经场与高斯）补上的部分。

## 2. 神经场与高斯表示（逐场景优化）

**要解决的问题**：在已知位姿的照片上，学出一个能渲染任意新视角的场景表示。三篇论文是同一条路线上的三步：先有“能用”的表示（NeRF），再把它变快（Instant-NGP），再换成可直接光栅化的显式表示（3DGS）。读法：读三篇的方法部分 [^3][^4][^5]。

### 2.1 NeRF：用神经网络表示连续的辐射场 [^3]

- **表示**：一个全连接网络，输入一个连续的五维坐标（空间位置 $(x,y,z)$ 加观看方向 $(\theta,\phi)$），输出该点的体密度与随视线变化的发射辐射（颜色）。
- **渲染**：沿相机射线取一批采样点，查询网络，再用经典体渲染把颜色与密度积分成像素颜色；体渲染天然可微，所以**唯一需要的输入就是带已知位姿的照片**。
- **两个关键技巧**：（1）位置编码，把输入坐标先变换成高频函数，使网络能表达高频细节；（2）分层采样，用“粗网络”的结果指导“细网络”在重要位置多采样，减少查询次数。
- **输入从哪来**：合成数据用真值位姿，真实数据用 COLMAP 估计位姿、内参与场景边界。
- **代价**：每个场景至少训练 12 小时；但网络权重只有 5 MB，比对比方法的体素网格小约 3000 倍。
- **论文自述的方向**：提高训练与渲染效率；可解释性（无法像体素或网格那样分析质量与失败模式）。

### 2.2 Instant-NGP：多分辨率哈希编码 [^4]

- **动机**：NeRF 的全连接网络训练与推理慢。思路是用一个小网络加一个可训练的“输入编码”，把计算量从网络转移到查表。
- **多分辨率哈希编码**：编码参数排成 $L=16$ 层，每层最多 $T$ 个特征向量（$T$ 取 $2^{14}$ 至 $2^{24}$），每个特征 $F=2$ 维；各层对应的虚拟网格分辨率按几何级数从最粗 $N_{\min}=16$ 增加到最细 $N_{\max}=512$ 至 $524288$。
- **查询**：对一个空间点 $x$，在每一层找到它所在网格单元的 $2^d$ 个角点，用空间哈希函数 $h(x)=\left(\bigoplus_i x_i\pi_i\right)\bmod T$（$\pi_i$ 为大质数，$\pi_1=1$）把角点坐标映射到哈希表下标，取出特征，再按点在单元内的相对位置做 $d$ 线性插值，各层结果拼接后送入小网络。
- **碰撞**：多个网格点会落在同一个表项，其梯度相互平均，梯度最大（对损失最重要）的会占优势，所以哈希表自动把容量分给含精细细节的稀疏区域；多层结构让后面的小网络能区分碰撞。训练中不需要修改数据结构。
- **效率**：表查询是 $O(1)$ 且无分支，对 GPU 友好；整个系统用融合的 CUDA 内核实现，训练从小时降到秒至分钟，渲染 1920×1080 约数十毫秒。
- **与本板块的关系**：哈希编码以**空间坐标**为键，是“用位置编码组织特征”的典型；若改用网格编码做键（8-2 的设想），就把均匀的哈希替换为带层级与邻接的编码，但是否有益尚无证据。

### 2.3 3D 高斯泼溅：显式高斯加光栅化 [^5]

- **表示**：场景是大量三维高斯，每个高斯有位置、不透明度、各向异性协方差（由缩放与旋转构成）和球谐系数（负责随视线变化的颜色）。所需高斯数为 100 万至 500 万量级。
- **初始化**：用 SfM 免费得到的稀疏点云初始化高斯，不需要 MVS 点云；对合成数据可随机初始化。
- **自适应密度控制**：优化过程中交替地增加和偶尔删除高斯，以便在欠重建或过重建的区域调整容量。
- **渲染**：屏幕分成 16×16 的瓦片，把高斯按视锥与瓦片剔除并排序，每个瓦片一个线程块，按前到后累积颜色与 $\alpha$，饱和即停；整个流水线可微，因此反向传播的额外显存是每像素常数。
- **性能**：论文在 Mip-NeRF360 上报告训练 30K 迭代约 41 分钟，渲染约 134 帧每秒，显存约 734 MB（作为对照，Instant-NGP 约 5 至 8 分钟、约 10 帧每秒，Mip-NeRF360 训练 48 小时、0.06 帧每秒；数字取自论文表 1 的节选，仅作量级参考）。
- **局限（论文自述）**：观测不足的区域有伪影；会出现细长或“斑驳”的高斯；优化产生大高斯时偶有“跳变”伪影，部分源于光栅化器对高斯的简单剔除与可见性算法。

### 2.4 小结

| 方法 | 表示 | 输入 | 训练一个场景 | 渲染速度 | 与世界系的关系 |
| --- | --- | --- | --- | --- | --- |
| NeRF [^3] | 全连接网络 | 已知位姿的照片（COLMAP） | 至少 12 小时 | 慢 | 局部系，无世界系概念 |
| Instant-NGP [^4] | 小网络加哈希编码 | 同上 | 秒至分钟 | 数十毫秒（1080p） | 同上；哈希以空间坐标为键 |
| 3DGS [^5] | 三维高斯 | 同上，高斯由 SfM 稀疏点初始化 | 约数十分钟 | 实时 | 同上；高斯位置是显式的三维坐标 |

三者共同的前提是**位姿已知且在同一局部坐标系**，且场景规模有限；规模放大后的做法见第 3 类。显式坐标的高斯与隐式的神经网络，在“数值范围”上的敏感度也不同：高斯的位置直接存成单精度浮点（本文判断，未在论文中核对），若放在大坐标下会直接受精度影响，而 NeRF 与哈希编码把坐标先归一化到小范围再编码。

## 3. 逐场景优化的大场景方法：分块与层级

**要解决的问题**：城市级场景太大，一个模型装不下、训练太慢、渲染也慢。本类的共同思路是“分而治之”：把场景切成块，各块单独训练，再把结果合起来；差别在于块怎么划、训练数据怎么分、块边界怎么处理、怎么保持块间一致。这是与 8-1 的“块拼接”问题最相近的一类，所以读得较细。读法：下载 arXiv 版全文，读方法与实现部分，实验表未读。

**先说一个共同点**：这五篇都以 SfM（如 COLMAP）给出的相机位姿为输入，坐标是 SfM 的局部坐标系；在读到的文本中**没有出现 GPS、UTM、WGS84、ENU、ECEF 或 GNSS 等世界坐标的概念**（Mega-NeRF 只说相机的高度变化远小于水平方向的变化）。也就是说，它们解决的是“规模”，不解决“世界系”。

### 3.1 Mega-NeRF：空间网格加几何感知的像素划分 [^6]

- **场景划分**：把场景在俯视方向铺成一张**二维规则网格**，每个网格单元有一个质心 $n=(n_x,n_y,n_z)$，并有一个独立的 NeRF 子模块。因为场景内相机高度变化远小于水平变化，质心的高度统一取同一个值。论文试过 k-means 聚类和基于不确定性的划分，最后发现俯视二维网格“简单、预处理少、推理时点到质心的分配很快”。
- **子模块选择**：渲染时，对射线上的每个采样点，用离它最近的质心对应的子模块来算密度与颜色。
- **训练数据的划分（关键）**：不是按相机分，而是**按像素分**：一个像素被分给某单元，当且仅当这个像素的射线穿过该单元。因此图像 2 的像素会同时进入 A、B、F 三个单元的训练集，每个单元的训练集因而缩小约十倍。相邻单元之间设置 **15% 的重叠**，以减小块边界附近的伪影。模型起步时还不知道几何，初始分配基于相机位置；之后可用占用信息进一步剪掉被遮挡物挡住的射线，把训练集再缩小约一半。
- **外观嵌入**：给每张图一个外观向量，吸收大场景里不同图像之间的光照差异。
- **前景与背景**：前景体是包住所有相机位姿的区域，背景为互补区域，两者各用一个 Mega-NeRF；背景的参数化用一个比 NeRF++ 的单位球更紧的椭球。
- **快速渲染**：用八叉树缓存占用与颜色，并利用相邻帧的时间相干性。
- **规模**：用 8 个子模块；场景面积从 15 万到 130 万平方米量级。
- **块间一致性**：推理时每个点只问一个子模块，不做跨块融合，靠重叠训练与外观嵌入来减少接缝。

### 3.2 Block-NeRF：以街道路口为块，推理时合成 [^7]

- **划分**：每个路口放一个 Block-NeRF，覆盖路口及与之相连的街道，延伸到下一路口的 75% 处，于是相邻两块在连接街道上有 **50% 的重叠**，便于对齐外观。块的大小因此可变，必要时加“连接块”。每块只用其原点周围一定半径内的数据训练。
- **每个块内的改进**：外观嵌入（应对数月里不同天气与时段）、**学习位姿修正**（假设位姿已给，但为每段驾驶数据学一个受正则的平移与旋转偏移，联合优化）、可控曝光；并用语义分割去掉车辆与行人等可移动物体。
- **推理时合成**：对目标视角，先对半径内的所有块算一张可见性图，**可见性低的块直接丢弃**；其余块各自渲染颜色，再按**反距离加权** $w_i\propto d(c,x_i)^{-p}$（相机位置到各块中心的距离）在二维图像空间插值，得到平滑过渡。
- **外观匹配**：不同块的外观码是随机初始化的，同一个码在不同块里产生不同外观。做法是在相邻两块的**重叠区选一个两块可见性都高的三维位置**，冻结网络权重，只优化外观码，使相邻块在该位置的外观一致，从一个固定的目标外观出发逐块传播。
- **规模与数据**：Alamo Square 街区约 960 m × 570 m，分成 35 个 Block-NeRF；整体使用 280 万张图像，数据在 2021 年 6 至 8 月间由采集车采集。
- **要点**：合成与外观对齐都发生在**渲染时**，块之间的一致性靠重叠区与插值，不靠共同的全局场景表示。

### 3.3 CityGaussian：全局粗模型先行，块内细化，再按块做细节层级 [^8]

- **起因**：3DGS 在大场景里显存爆炸：24 GB 的 RTX 3090 在高斯数超过 1100 万时就内存溢出，而 1.5 km² 以上的城市区域可能需要 2000 万以上的高斯。
- **全局先验**：先用普通 3DGS 训练一个**粗略的全局高斯模型**，作为后续划分与对齐的基础；论文认为直接对 COLMAP 点云做分块，缺少深度约束与全局意识，会在块外产生很多几何不准的漂浮物，融合时相互干扰。
- **高斯划分**：把无界区域“收缩”到一个归一化的有界立方体，再做**均匀网格划分**，以平衡各块的工作量。
- **训练数据划分**：一张图被分给某一块，当且仅当它的相机位姿在块内，或者该块对这张图的渲染有“相当的贡献”（自适应地扩大选择）。
- **块内训练**：各块并行训练，用全局粗模型作先验指导，避免块间相互干扰并**实现无缝融合**，最后把各块合并成整个场景。
- **细节层级（LoD）**：对融合后的高斯生成压缩版本（点数与特征更少），渲染时以前面划分的块为单位，先判断哪些块可能在视锥内，再对**远离相机的块换用压缩版本**，只把必要的高斯送入光栅化，使大场景在不同尺度下保持实时。
- **块边界**：靠全局先验与训练数据的自适应扩大，而非固定的重叠比例。

### 3.4 CityGaussianV2：换成二维高斯，面向几何精度与并行效率 [^9]

- **动机**：3DGS 的图元无序，不贴合真实表面，大场景里几何精度不足。V2 改用 2D 高斯泼溅（把一个维度压扁，使深度和法向更明确），并解决其收敛慢与规模难的问题。
- **做法**：分解梯度的稠密化和深度回归，以消除模糊并加速收敛；**拉长度过滤器**，抑制二维高斯退化造成的高斯数量爆炸；并改造 CityGaussian 的并行训练流程，称可实现最高 10 倍压缩、至少 25% 的训练时间节省与约 50% 的显存下降。
- **对照**：论文表中给出，把 CityGS 的并行策略直接用到二维高斯上，大多数场景会内存溢出；并建立了大场景的几何评测基准。
- **与世界系**：几何精度评测用带激光雷达的航拍数据集；读到的文本没有说明评测前如何对齐到真值坐标系，本文不作推断。

### 3.5 HUG：基于可见性的划分，块内用层级神经高斯 [^10]

- **动机**：已有的分块方法往往在块边界周围训练大片冗余区域来保证边界精度，造成计算浪费；且划分过程本身也慢。
- **可见性划分**：以 COLMAP 的稀疏点云为基础，把场景**均匀划分**成块（块大小受控以防显存溢出）；对每个块，把块内点投影到各视图，据此选出相关视图，并用一个由可见性训练的非线性分类（论文称 SVM 掩码）圈出视图里属于块内的区域，让训练集中在块内。论文称在 MatrixCity 上划分只需约 1 分钟，而 CityGS 约需 2 小时。
- **块内表示**：基于 Scaffold-GS 与 Octree-GS，以**锚点生成神经高斯**，并用八叉树层级实现细节层级；训练时对块内区域做带掩码的 L1 与 SSIM 监督，并用“层级加权”的图像监督。
- **融合**：各块训练完后合并，完成局部场景融合。
- **要点**：它明确把“边界冗余”当作问题，用掩码集中监督块内，代价是依赖更精确的块内区域判定。

### 3.6 对照与小结

| 方法 | 表示 | 块的划分 | 训练数据分配 | 块边界与融合 | 层级 | 世界系 |
| --- | --- | --- | --- | --- | --- | --- |
| Mega-NeRF [^6] | NeRF | 俯视二维规则网格，质心高度取同一值 | 按像素：射线穿过单元即分配；15% 重叠 | 推理时每点问一个子模块；靠重叠与外观嵌入 | 前景与背景；八叉树缓存 | 否，SfM 局部系 |
| Block-NeRF [^7] | NeRF | 每路口一块，相邻块 50% 重叠，大小可变 | 原点半径内的数据 | 渲染时丢弃低可见性块，反距离加权，外观匹配 | 否 | 否 |
| CityGaussian [^8] | 3DGS | 收缩到有界立方体后均匀网格 | 位姿在块内或对块有贡献 | 全局粗模型作先验，并行训练后合并 | 块级 LoD（压缩） | 否 |
| CityGaussianV2 [^9] | 2DGS | 沿用 CityGaussian | 沿用 | 沿用并优化并行流程 | 沿用 | 否 |
| HUG [^10] | 神经高斯（锚点） | COLMAP 稀疏点云上的均匀网格 | 可见性选视图加掩码 | 块内监督，合并融合 | 八叉树 LoD | 否 |

**对板块八的含义**（本节归纳，部分为推断）：

1. **划分的基准各不相同**：规则俯视网格（Mega-NeRF）、路口与街道（Block-NeRF）、收缩后立方体的均匀网格（CityGaussian）、稀疏点云上的均匀网格（HUG）；它们都建立在场景自己的局部坐标上，块没有全局地址，也没有统一的尺度或层级约定。网格单元划分（DGGS）恰好可以提供一套全局统一的、层级嵌套的块地址，这是它的潜在价值（假说，待 8-1 验证）。
2. **块边界一致性有三种做法**：重叠训练（Mega-NeRF 15%、Block-NeRF 50%）、全局先验引导（CityGaussian）、块内掩码监督（HUG）；对应的代价分别是冗余计算、需先训一个全局粗模型、对块内区域判定的依赖。8-1 的指标（接缝、块间偏移）正可借来比较前馈式场景下的同类做法。
3. **层级（LoD）**：CityGaussian 与 HUG 用块或八叉树做层级，与网格的层级编码有对应关系；是否能直接以网格编码取代这些自建层级，属于 8-2 的问题。
4. **都不涉及世界系与块间偏移**：位姿由 SfM 给出，输出在局部系；这与第 5、6 类（卫星与地理参考的前馈方法）形成对照。
5. **逐场景优化与前馈的差异**：这一类的块要各自训练，块间一致性靠训练期的重叠或先验；前馈式方法的块在推理期各自一次前向，没有训练期的共同优化，接缝只能靠重叠推理、融合与后处理来缓解，这使 8-1 的块拼接基准更有意义（推断）。

## 4. 前馈式重建：一次前向得到几何或高斯

**要解决的问题**：不想为每个场景单独训练或迭代优化，而是用一个预训练模型“看一眼照片就给出三维结果”。

这一类可分为两条线，用途不同，对板块八的意义也不同：

| 线索 | 代表 | 输入 | 输出 | 目的 |
| --- | --- | --- | --- | --- |
| A 点图与结构 | DUSt3R、MASt3R、VGGT、MapAnything | 照片（MapAnything 可附加位姿、内参、深度等先验） | 每像素的三维坐标（点图），或深度加相机位姿 | 恢复几何与相机 |
| B 前馈渲染 | pixelSplat、MVSplat | 少数已知位姿的照片 | 三维高斯 | 渲染新视角 |

本节所述内容读自各论文的方法与训练部分（2026-10-15 读 arXiv 版全文的相应章节），未读的部分（如全部实验表）不作结论。

### 4.1 DUSt3R：用“点图”把几何回归变成一个网络任务 [^11]

- **点图**：对一张 $W\times H$ 的照片，点图是同尺寸的三维坐标场 $X\in\mathbb R^{W\times H\times 3}$，每个像素对应一个三维点。论文假设每条射线只击中一个点，忽略半透明表面。
- **输入与输出**：一对照片 $I_1,I_2$ 输入，输出两张点图 $X^{1,1}$ 和 $X^{2,1}$，**都表示在第一张照片的相机坐标系下**，另有各像素的置信度。第一台相机在原点，第二台相机的位置未知、由两张点图隐含给出。
- **网络**：两张图先用共享权重的视觉变换器（ViT）编码，再经两个互相交换信息的变换器解码器（逐层先自注意力、再对另一视图的交叉注意力），最后由回归头输出点图和置信度。
- **损失与尺度**：损失是预测点图与真值点图的欧氏距离，按像素的置信度加权，并加 $-\alpha\log C$ 的正则让网络可以对难预测区域（如天空）给低置信。为了与真值的尺度无关，预测与真值先各自除以所有有效点到原点的**平均距离**再比较。因此输出的尺度只是相对的，不是米。
- **多于两张**：先在照片间建一个“谁与谁有重叠”的图，对每个相连的照片对用网络预测点图，再做**全局对齐**：给每一对求一个位姿 $P_e$ 和缩放 $\sigma_e$，把所有成对点图旋转、缩放到公共坐标系，最小化各点与公共点图 $\chi$ 的置信度加权距离。这是后处理的迭代优化，不是网络本身的前向。
- **可恢复的量**：深度、相机内参（相机主点假设在中心，只估计焦距）、相对位姿（对两张点图做 Procrustes 对齐或用 PnP 加 RANSAC）、像素匹配（点图上的最近邻）。
- **训练数据**：八个数据集混合，含 Habitat、MegaDepth、ARKitScenes、BlendedMVS、ScanNet++、CO3D-v2、Waymo 等，既有室内也有室外，既有合成也有真实。

### 4.2 MASt3R：加上匹配与度量尺度 [^12]

- **新增描述子头**：在 DUSt3R 的基础上增加一个输出稠密局部特征的头（两层 MLP，特征归一化到单位长度），用 InfoNCE 损失训练，让同一三维点在两张图上的特征互相匹配。动机是点图回归本身有噪声，且 DUSt3R 没有被明确训练去做匹配。总损失为回归损失加匹配损失。
- **快速互近邻与粗到细**：稠密匹配的互近邻搜索是二次复杂度，论文提出把搜索加速近两个数量级的方案，并用多尺度的粗到细匹配处理高分辨率图像。
- **度量预测**：论文指出尺度不变并非总是需要，如无地图视觉定位就要求度量尺度；因此当真值点图是度量时，**不再对预测与真值做尺度归一化**（令 $z:=\hat z$），网络直接学习输出以米计的点图。训练的 14 个数据集中 10 个有度量真值。
- **局限**：论文没有单独的局限性小节；其评测集中于匹配、定位与多视图立体，未见对大范围场景的专门讨论。

### 4.3 VGGT：一个大变换器直接预测相机、深度、点图 [^13]

- **规模与输入**：约 12 亿参数，输入一到数百张照片；训练时每个批次从某个场景随机取 2 至 24 帧，图像最大边 518 像素，在 64 张 A100 上训练九天、16 万次迭代。
- **架构**：用 DINOv2 把每张图切成块并编码；每张图额外加一个相机令牌和四个寄存器令牌；变换器交替使用“帧内自注意力”和“跨帧全局自注意力”共 24 组，不使用交叉注意力。第一帧的相机令牌是单独的一组可学习令牌，使模型能区分“参考帧”，并在**第一台相机的坐标系**下表示所有预测。
- **输出**：每帧的相机参数（外参与内参）、深度图、点图、用于点跟踪的特征，深度、点图和相机之间存在冗余，但论文发现显式训练全部输出能提升性能。
- **尺度与坐标约定**：真值先全部转到第一台相机系，再计算所有三维点到原点的平均欧氏距离，用它归一化相机平移、点图和深度；论文特别说明，**不对网络输出做归一化，而让网络从数据中学习这个归一化约定**。
- **损失**：相机的 Huber 损失、带不确定性的深度损失（另加梯度项）、点图损失，以及降权为 0.05 的跟踪损失。
- **训练数据**：十余个数据集，含 CO3Dv2、BlendedMVS、DL3DV、MegaDepth、ScanNet、Habitat、Virtual KITTI、Aria 系列等，标注来自传感器、合成引擎或 SfM。
- **速度与限制**：几秒内完成；论文称 DUSt3R 在 32 帧以上就会显存不足。局限包括不支持鱼眼与全景、极端旋转时性能下降、大幅非刚性变形会失败。

### 4.4 MapAnything：可选地接收位姿、内参、深度，输出度量尺度 [^14]

- **分解表示**：不再直接输出点图，而把场景分解为“深度图、局部射线图、相机位姿、一个度量尺度因子”；前三项是相对（未定尺度）的，尺度因子把它们“升级”为全局一致的度量坐标系。
- **可选输入**：输入除照片外，还可附带内参（射线）、位姿、深度或部分重建。位姿的**旋转与平移分开编码**，以支持只有部分信息的情形，论文明确以 IMU 与 GPS 先验为例；深度与位姿的归一化也分开处理。
- **网络**：各模态先编码到同一潜空间并相加，给第一视图加固定的参考视图嵌入，追加一个可学习的尺度令牌；交替注意力变换器之后，用一个 DPT 解码每个视图的稠密输出，一个池化头预测各视图在视图 1 坐标系下的位姿，尺度令牌经 MLP 得到度量尺度因子。
- **训练**：两阶段课程，只用最多 4 个视图训练，却能泛化到 50 个视图；第一阶段用 64 张 H200 训练约六天。可从只有“相对尺度”标注的数据集学习，因为尺度被分解出来。发布了两个模型：Apache 2.0 许可（用 6 个数据集训练）与 CC-BY-NC 许可（13 个数据集）。
- **局限（论文自述）**：**不显式考虑几何输入中的噪声或不确定性**；可扩展性受限于“输入像素与输出场景表示一一对应”，大场景的表示与解码有待研究。

### 4.5 pixelSplat 与 MVSplat：已知位姿的前馈高斯 [^15][^16]

这条线解决的是新视角合成，输入是**已知位姿**的少数照片。

- **pixelSplat**：从一对照片直接预测像素对齐的 3D 高斯，可实时渲染。两个难点：（1）真实数据中的相机位姿只能重建到任意尺度，论文设计多视图极线变换器来推断每个场景的尺度；（2）直接优化高斯参数易陷入局部极小，而前馈情形下又不能用单场景那种不可微的分裂与剪枝，故改为预测深度上的稠密概率分布，再从中采样高斯均值，并用重参数化技巧保持梯度。局限（论文自述）：对两个视图的高斯只做并集而不融合去重；不生成不可见部分；视图增多时极线注意力的显存开销过大。
- **MVSplat**：用平面扫描构造代价体（跨视图特征相似度沿一组深度假设排列），据此估计深度并定位高斯中心，其余高斯参数联合学习，仅用光度损失监督；在 RealEstate10K 与 ACID 上达到 22 帧每秒的前馈速度，参数量约为 pixelSplat 的十分之一、推理快一倍以上。

### 4.6 对照与小结

| 方法 | 位姿要求 | 输出 | 参考系与尺度 | 视图数 | 发布 |
| --- | --- | --- | --- | --- | --- |
| DUSt3R [^11] | 不需要 | 成对点图，多图靠全局对齐 | 第一张图的相机系；相对尺度 | 成对 | 未核对 |
| MASt3R [^12] | 不需要 | 点图加匹配特征 | 第一张图的相机系；有度量真值时输出度量尺度 | 成对 | 未核对 |
| VGGT [^13] | 不需要 | 相机、深度、点图、跟踪 | 第一台相机系；由训练学到的归一化 | 一到数百 | 论文称代码与模型公开 |
| MapAnything [^14] | 可选（含旋转、平移分开的先验） | 深度、射线、位姿、度量尺度因子 | 视图 1 系，度量尺度 | 训练 ≤4，泛化到 50 | Apache 2.0 与 CC-BY-NC 两个模型 |
| pixelSplat [^15] | 需要（尺度任意） | 高斯 | 由已知位姿定义，尺度由网络推断 | 两个，多视图开销大 | 未核对 |
| MVSplat [^16] | 需要 | 高斯 | 同上 | 少数 | 论文备注称代码公开 |

**与世界系的关系**（本节归纳，部分为推断）：

1. 这些模型的输出几乎都落在**第一张照片（或参考视图）的相机坐标系**，尺度由数据相关的归一化约定（点到原点的平均距离）或网络隐含给出；要得到 WGS84，必须再做一次外部的相似变换，这正是 Cross-View Splatter 等工作在每个样本里重新定义局部系的原因（见第 6 类）。
2. “按场景内点到原点的平均距离归一化”这一约定在街景与室内场景里合理，在深度范围跨度极大的航拍与卫星场景里是否合适，没有看到论文讨论（推断，待验证）。
3. MapAnything 的“位姿旋转与平移分开输入、可附 GPS 与 IMU 先验、输出度量尺度”最接近“把世界系先验注入前馈模型”，但论文自述不处理输入噪声；民用 GNSS 误差是米级，因此其绝对精度上限须实测。
4. 一次推理能容纳的视图和输出都有限（输出与输入像素一一对应，MapAnything 与 pixelSplat 均自述大场景或多视图的可扩展性问题），大范围必然要分块，这就引出 8-1 的块拼接问题。
5. DGGS 的可能角色（假说，待 8-1 与 8-2 检验）：以网格单元定义每块的参考系与尺度，用层级给出尺度，替代按场景统计量归一化，使不同块的坐标与尺度约定一致、块边界重合。

## 5. 卫星摄影测量与 RPC：天然带地理参考

**要解决的问题**：从卫星影像恢复地表高度，结果要落在地理坐标系中。

**核心做法**：卫星影像随附 RPC，把地理坐标直接映射到像素，不需要 SfM 估计位姿；传统流程用多视影像做立体匹配得到高度，并以块调整（用控制点校正 RPC 的系统偏差）提高绝对精度 [^17]。Sat-NeRF 把 NeRF 扩展到 RPC 相机，并建模瞬态物体与阴影 [^18]。GeoRay 把前馈式模型接到 RPC 上，直接输出大地坐标系下的高度场，并显式估计整块的高程基准偏移（8-1 已通读其源码）[^19]。

**局限与关系**：影像带有地理参考，是“直接在世界系生成”最自然的一类；但输出是 2.5D 的高度场，窗口很小（GeoRay 为 256 像素），没有大范围的镶嵌流程。

## 6. 带地理参考的前馈视图合成与前馈式大场景生成

**要解决的问题**：把前馈式方法用到地理空间，并走向大范围。本类分三组：（A）带地理参考的前馈视图合成与度量恢复（Cross-View Splatter、卫星度量尺度一篇），（B）稀疏航拍的前馈城市重建（AnyCity），（C）从布局、高度图或卫星图出发的生成式大场景（CityDreamer、GaussianCity、Sat2Scene、InfiniCity）。读法与第 4 类相同：读 arXiv 版的方法与实现部分，实验表未读。前三篇是 2026 年预印本，未经同行评议。

### 6.1 Cross-View Splatter：地面照片加卫星图，在统一坐标系下预测高斯 [^20]

- **输入与目标**：任意数量、位姿未知的地面照片（只需要它们的 GPS 位置），加一张按 GPS 从地图服务检索到的正射卫星图和对应的地形高度；预测地面与鸟瞰两套 3D 高斯，放在同一坐标系里，用以扩大场景覆盖、改善新视角合成。
- **坐标约定**：以第一张地面图像 $I_0^{\text{ground}}$ 作为原点（单位位姿），它同时决定零高度位置和卫星图的中心；卫星图的朝向对齐到 $I_0$ 的视线方向，使视线在卫星图中朝上；其余地面图像表示成相对 $I_0$ 的位姿。论文**假设地面与卫星之间的变换是已知的三自由度**（平面位置与朝向）。
- **网络**：地面分支沿用 VGGT 的结构（DINOv2 切块、相机令牌加寄存器令牌、帧内与全局交替注意力），预测相机位姿、内参、深度与高斯参数；卫星分支把正射图编码为令牌，再用 12 层地面与卫星令牌之间的双向交叉注意力融合；模型由 AnySplat 初始化。
- **卫星分支的输出**：正射影像没有透视位姿和深度，所以改为回归**相对 $I_0$ 的高度图**加置信度；高度转三维点利用卫星图已知的空间分辨率（像素每米），按正交投影关系把像素换算成世界坐标，同时论文把高度图和分辨率纳入同一尺度归一化。置信度用来缓解地形真值带噪声的影响。
- **尺度归一化**：沿用 VGGT 一类的“每批 $\ell_2$ 缩放”，推理时所有预测都表达在同一个归一化坐标系里。
- **损失**：地面深度与相机的回归、高度图的置信度加权损失、地面与卫星高斯的渲染损失、两者并集在地面与鸟瞰视角的渲染损失，以及天空正则；训练 4 天，2 张 A100，批大小 10，输入 518×518，卫星与地形裁剪的空间范围固定为 244 m。
- **数据**：Metropolis、VIGOR（全景图裁成 90° 透视图）、MapFree、Virtual KITTI 2、DL3DV；基准场景靠人工把 COLMAP 重建对齐到卫星图。
- **局限**：一个场景一块卫星图，未讨论多块或更大范围的拼接；相机高度在所有数据集中固定为 2 m，留有一个未解决的自由度；训练数据以美国城市为主；卫星影像因许可不发布，只提供查询代码。

### 6.2 卫星引导的度量尺度恢复：用卫星图把尺度与位姿拉进“卫星坐标系” [^22]

- **思路**：前馈重建只得相对结构，却缺尺度；用粗 GPS 检索一块卫星图作为全局度量参照，让网络据此推断绝对尺度与度量位姿，**只需要粗 GPS（训练时以 ±20 m、±10° 扰动模拟）**。
- **网络**：以 $\pi^3$（VGGT 一类的前馈重建模型）为主干，冻结原模型，复制出一个可训练的卫星分支，卫星分支处理卫星图，并通过双向交叉视图交互把度量线索注入；另有场景与卫星的对齐损失。
- **输出的形式**：对原模型输出的相对位姿与点图，网络预测一个全局尺度 $\beta$、一个坐标偏移 $C=(C^r,C^t)$ 和一个几何修正 $\Delta X$：位姿变为 $[C^r T^r,\ \beta T^t + C^t]$，点图变为 $\beta(X'+\Delta X)$。即把相对重建通过“相似变换加修正”送入卫星坐标系，这与第 1 类里“局部系到世界系是相似变换”的说法完全对应。
- **训练**：100 轮，每次随机取 1 至 3 张地面图；前 80 轮优化尺度与偏移，后 20 轮做几何修正；每块卫星图覆盖 250 m×250 m。数据为 KITTI、nuScenes、Oxford RobotCar 的街景。
- **局限**：论文没有单独的局限小节；未命名卫星坐标系的具体定义，也不涉及大范围拼接。

### 6.3 AnyCity：稀疏航拍的前馈城市重建 [^21]

- **问题**：稀疏航拍视图的证据严重不均衡——屋顶与空地被反复观测，立面、远处建筑与被遮挡区域很少被约束。单一的确定性前馈回归会产生重影、立面模糊、纹理拉伸；而直接引入生成式先验，又让模型分不清“观测到的”与“编出来的”。
- **做法**：把重建拆成“观测支撑的骨架”与“受控的补全”。先由一个前馈多视图主干预测**几何潜变量** $Z_{\text{geo}}$，只承载输入直接支持的结构；再用“骨架条件化的补全令牌”读取骨架并预测门控的残差 $\Delta Z$，最终 $Z_{\text{final}}=Z_{\text{geo}}+\Delta Z$，解码成 3D 高斯。视频扩散模型（Wan 2.2，LoRA 适配）只作为潜变量的条件，通过门控交叉注意力调制令牌，而最终高斯仍由重建模型解码，并受“保持观测”的目标约束。
- **训练**：分两阶段：第一阶段在 MatrixCity 上训练骨架（有真值深度与法向），输入 448×448；第二阶段加入补全令牌与视频先验，并用“稠密视图教师”向稀疏输入蒸馏；推理时去掉教师，单次前馈、约 1 s。
- **与世界系的关系**：论文强调“绕过精确位姿与 SfM 初始化”，位姿由网络内部预测；**读到的文本没有度量尺度、世界坐标系或拼接的内容**，评测只报渲染指标。未声明发布代码、权重或数据。

### 6.4 生成式的大场景：从布局、高度图或卫星图“无中生有”

这一组不是“重建”，没有观测可核对，三维结果的世界系精度难以验证；“无界”靠的是**把全局结构规划与局部细化分开**：

| 工作 | 输入 | 表示与做法 | “无界”靠什么 | 数据 |
| --- | --- | --- | --- | --- |
| InfiniCity [^26] | 随机噪声 | 三阶段：先用基于块的隐式图像合成生成任意大小的二维鸟瞰图（卫星图、语义图、高度图等多模态），再用八叉树体素补全提升为三维，最后用体素神经渲染贴纹理 | 二维鸟瞰图可任意大，再补全为三维八叉树体素 | HoliCity |
| CityDreamer [^23] | 随机噪声 | 先生成任意大的城市布局，再分别生成背景与建筑实例；背景与建筑用不同的神经场（生成式哈希网格与周期位置编码），以鸟瞰图场景表示和体渲染合成 | 布局生成器可生成任意大的城市布局 | OSM（80 个城市，覆盖超过 6000 km²）、Google Earth Studio（纽约，400 条轨迹、2.4 万张图） |
| GaussianCity [^24] | 鸟瞰图（语义、密度、高度） | 把城市表示为紧凑的“鸟瞰点”（BEV-Point），再由空间感知的点解码器（点序列化加点变换器）预测 3D 高斯属性；单次前馈 | 鸟瞰点使显存随点数增长保持不变；论文称此前的高斯表示在 10 km² 的场景需数百 GB 显存 | 对比评测见 GoogleEarth 数据集；对 CityDreamer 提速约 60 倍（10.72 对 0.18 帧每秒） |
| Sat2Scene [^25] | 单张卫星图（得到的几何） | 在三维稀疏点表示上做扩散，先为给定几何生成点级纹理颜色，再前馈转为场景表示，可渲染任意视角 | 稀疏点表示避免稠密体素占用 | HoliCity、OmniCity（含卫星图） |

CityDreamer 论文自述的局限：布局靠把体素拉升到某一高度，凹形几何（山洞、隧道）无法建模；推理时建筑逐个生成。

### 6.5 对照与小结

| 工作 | 输出 | 世界系定义 | 范围 | 拼接 | 是否生成 |
| --- | --- | --- | --- | --- | --- |
| Cross-View Splatter [^20] | 地面与鸟瞰高斯 | 每样本局部系，原点取首张地面图，GPS 检索卫星图 | 244 m | 未讨论 | 否（重建） |
| 卫星度量尺度 [^22] | 度量点图与位姿 | “卫星坐标系”，由尺度、偏移与修正得到 | 250 m 见方 | 未讨论 | 否 |
| AnyCity [^21] | 3D 高斯 | 位姿网络内部预测，未说明世界系 | 未给出 | 未讨论 | 重建加受控补全 |
| InfiniCity、CityDreamer、GaussianCity、Sat2Scene [^26][^23][^24][^25] | 体素、神经场、高斯或点 | 以鸟瞰图或布局的像素坐标为准，非地理坐标 | 可无限外推 | 以布局或二维图外推实现 | 是 |

**与世界系的关系**（本节归纳，部分为推断）：

1. **“局部系加相似变换”是这一类的共同做法**：Cross-View Splatter 以首张图为原点并靠已知的三自由度变换对齐卫星图，卫星度量尺度一篇用尺度加偏移加修正进入卫星坐标系；二者都只处理 250 m 量级的一块，没有一套把很多块拼到同一世界系的约定。
2. **度量与世界系常靠“卫星图作参照”**：卫星图自带像素分辨率（像素每米）与地理位置，两篇都用它来补尺度；这说明地理参考的来源可以是已有的地图数据，不一定是 GNSS 位姿。
3. **生成式工作的“无界”是在像素或布局空间里外推**，坐标不是地理坐标；它们的鸟瞰图、布局与高度图本来就是地图形式的栅格，若要落到 WGS84，需要先决定栅格的地理定位与分辨率，这与 DGGS 的单元划分天然对应（假说，待验证）。
4. **未见块间拼接的系统方法**：6.1 与 6.2 均固定一块范围；6.4 靠生成器自身外推，不处理“多个独立前馈结果的拼接”。这是 8-1 要填的位置。

## 7. 位姿与度量尺度的外部先验

**要解决的问题**：前馈模型只给相对结构（第 4 类），要得到世界系结果，必须引入外部信息：一个把相对尺度变成米的尺度，以及把局部系对齐到世界系的位姿。外部信息通常来自 GNSS（卫星导航定位）、IMU（惯性测量，给出加速度与角速度）、控制点，或者卫星图像（第 6 类）。这些信息怎么与前馈模型结合，有四种思路：

| 路径 | 做法 | 代表 |
| --- | --- | --- |
| A 事后配准 | 先得到相对重建，再用 GNSS 或控制点对相机位姿做一次相似变换配准 | 通行做法，没有对应文献 |
| B 作为网络输入 | 把位姿、内参、深度等先验编码后输入网络，让网络学会利用 | MapAnything [^14]、OmniVGGT [^28] |
| C 作为联合优化的约束 | 把前馈模型的输出当作视觉约束，与 IMU、GNSS 一起放进因子图优化 | MASt3R-Fusion [^27] |
| D 外部地图或影像作度量参照 | 用卫星图提供尺度与位置 | 卫星度量尺度一篇 [^22]、Cross-View Splatter [^20] |

本节读 B、C 两路的三篇（MapAnything 已在 4.4 读过，这里只补与先验相关的部分；OmniVGGT 与 MASt3R-Fusion 读 arXiv 版全文的方法部分，实验表未细读），D 路见第 6 类。

### 7.1 先说清楚 GNSS 能给多少精度

- **民用单点定位的典型精度**：美国 GPS 官方网站称，带 GPS 的智能手机在开阔天空下通常精确到约 4.9 m 半径内，靠近建筑、桥梁和树木时变差；标准定位服务的指标针对的是天上信号本身的测距误差（日均全球平均小于等于 2.0 m、概率 95%），不适用于接收机；高端用户用双频接收机或增强系统提高精度 [^29]。一项 2020 年对三款安卓手机的研究给出水平精度约 4.5 至 7.3 m（据检索摘要，未读原文）。
- **RTK 等高精度方式的现实问题**：MASt3R-Fusion 的实验中，真实 RTK 观测“出现很多粗差与不可用时段”，单靠 GNSS 的位置估计需要与视觉和惯性联合才能稳定 [^27]。
- **与块拼接尺度的比较**（本文归纳）：前馈块内的细节精度在厘米到米级（GeoRay 的绝对平均误差约为 1.8 到 3 m，见 8-1），而民用 GNSS 是米级。因此块间的位置偏移往往大于块内精度，必须用重叠区、控制点或卫星图去校正，不能只靠 GNSS。

### 7.2 MapAnything：位姿先验作为可选输入 [^14]

（结构见 4.4，此处只补与先验相关的）

- **位姿先验的编码**：论文说明，为了支持“只有旋转或只有平移”的情形（例如只有 IMU 或 GPS 先验），旋转与平移分开编码；又因为平移与尺度纠缠，对深度与位姿的归一化也分开处理；同时输入深度与位姿时，在训练目标中把预测的深度与位姿一起归一化，以保证多视图一致。
- **输出**：各视图的位姿在视图 1 的坐标系下，由一个度量尺度因子升级为度量；因此即使输入了位姿先验，输出仍落在视图 1 系，不是世界系，须另外变换。
- **自述局限**：不显式处理几何输入中的噪声与不确定性。

### 7.3 OmniVGGT：用 GeoAdapter 把相机与深度注入 VGGT [^28]

- **动机**：VGGT 只吃照片，忽略了容易得到的相机内参、位姿与深度。目标是让模型在训练和推理时都能接收任意数量、任意组合的辅助几何模态。
- **GeoAdapter**：由相机适配器与深度适配器组成，各含“归一化、编码、注入”三步。
  - 相机适配器：先把坐标系原点对齐到第一台相机，用其余相机到原点的平均距离作为尺度因子，归一化所有位姿；相机位姿是全局量，直接注入会破坏大模型的特征空间，因此用**零初始化的卷积**，让注入强度从零逐渐增加。
  - 深度适配器：把深度图与有效掩码拼成两通道，经专门的卷积层转成令牌，缺失处用占位令牌；论文发现给深度分支再加零卷积反而有害。
  - 对没有辅助信息的视图，用占位令牌代替。
- **随机多模态融合训练**：每个样本随机抽取模态子集，使测试时可接受任意数量的模态，也避免过拟合辅助信息；约 19 个公开数据集训练。
- **输出**：深度图、相机位姿与内参、三维点图及置信度；推理速度与 VGGT 相当。
- **与世界系的关系**：位姿归一化仍以第一台相机为原点、以相机间平均距离为尺度，因此是“相对于首帧的相对输入”，没有 GNSS 或地理坐标的概念；也没有噪声模型，随机丢弃模态不等于鲁棒地处理带误差的先验（本文判断）。
- **发表信息**：arXiv 页面只给了项目主页，检索到的会议页面显示为 CVPR 2026，页码未核对。

### 7.4 MASt3R-Fusion：把前馈点图并入 IMU 与 GNSS 的因子图 [^27]

这是第 7 类中唯一把 GNSS 与前馈模型做概率融合、并显式处理导航坐标系的工作。

- **思路**：论文认为，前馈点图回归的流程丢掉了传统多传感器融合的优势（概率融合）。于是保留传统 SLAM 的“状态加因子图”骨架，把前馈模型输出的点图当作视觉约束放进去。
- **前端：成对点图与匹配**：两张图输入 MASt3R 类的前馈模型，得到统一参考系下的两张点图和描述子图，由此稠密匹配；一个新帧的位姿通过与前一关键帧的点图对齐来跟踪。
- **状态**：每个关键帧的 SE(3) 位姿、一个尺度参数 $s_i$（点图“无尺度”，要靠它与 IMU 恢复度量）、速度和 IMU 偏置；**所有状态用双精度（float64）维护**。
- **视觉约束**：不同于束调整（联合优化地标与位姿、先验知识少），这里是“点图对齐”：只优化相机位姿与点图的尺度，建立在已知的无尺度三维结构之上；约束写成 Sim(3) 对齐的海森矩阵形式，并经雅可比转换到绝对状态，同时用网络输出的置信度与 Huber 核加权；残差与海森矩阵都在 GPU 上算。
- **后端：分层因子图**：实时滑动窗口优化（保持固定数量的关键帧，边缘化旧状态以保留信息）加全局优化（回环、IMU 预积分、GNSS 位置）。
- **GNSS 因子**：残差为 $T_{nw}\circ T_i\circ T_{bc}\circ t_{cg}-\tilde t_{ng,i}$，其中 $\tilde t_{ng,i}$ 是导航系下测得的 GNSS 相位中心位置，$T_{nw}$ 是由**初始对准**得到的固定的“世界到导航系”变换，另有 IMU 与 GNSS 的杆臂；GNSS 与关键帧时间不同步时，加一个临时的预积分项来衔接。回环约束用 Cauchy 鲁棒核抑制错误回环。
- **结果（论文自述）**：RTK 观测有粗差与不可用时段，松耦合的 VINS-Fusion 无法在 GNSS 退化时间段抑制位置误差；论文称该方法结合回环后可在 GNSS 退化的时段保持分米级精度；在模拟的 100 秒 GNSS 中断下，全局因子图的轨迹平滑多数仍在亚米级；能在 8 GB 显存上处理任意长序列。（表 VI 的数字在文本提取中版式混乱，未引用具体数值。）
- **发布**：论文称代码将开源，是否已发布未核对。
- **局限**：这是一个 SLAM 系统，输出的是轨迹与稠密点图，面向机器人与自动驾驶的序列数据，不是单次前馈的大场景生成；坐标系用的是导航系与世界系的显式变换，未涉及网格或块划分。

| 工作 | 先验注入 | 噪声处理 | 世界或导航系 | 输出 |
| --- | --- | --- | --- | --- |
| MapAnything [^14] | 可选输入，旋转与平移分开编码 | 不显式处理（自述） | 视图 1 系，度量尺度 | 深度、射线、位姿 |
| OmniVGGT [^28] | GeoAdapter（零卷积），位姿与深度 | 无噪声模型；随机丢弃模态 | 首帧相机系，按相机间平均距离归一化 | 深度、位姿、点图 |
| MASt3R-Fusion [^27] | 因子图中的 IMU 与 GNSS 因子 | 鲁棒核、边缘化、概率加权 | 显式的导航系与世界系变换，float64 状态 | 轨迹与稠密点图 |
| 卫星度量尺度一篇 [^22] | 卫星图参照，粗 GPS 检索 | 以 ±20 m 的 GPS 扰动训练 | “卫星坐标系” | 度量点图与位姿 |

**对板块八的含义**（本节归纳，部分为推断）：

1. **只有因子图路线明确处理了世界系与数值精度**：MASt3R-Fusion 用显式的 $T_{nw}$ 与 float64，网络输入路线（MapAnything、OmniVGGT）都把先验当作相对于首帧的相对量，没有地理坐标概念，也都不处理先验噪声。
2. **GNSS 的误差决定绝对精度上限**：民用米级，与块内精度相当甚至更大；块拼接时每块一个整体偏移，靠 GNSS 难以校正，需用重叠区与稀疏控制点。GeoRay 的实验给了一个量级：0、1、10 个控制点下绝对平均误差为 2.99、2.14、1.82 m，一个控制点就能解决整块的高程偏移（见 8-1）。
3. **因子图视角可借用到块拼接**（假说，待 8-1 与 8-3 检验）：每个块是一个节点（带一个相似变换或偏移），重叠区与控制点是边与约束，全局求解块间偏移；网格单元给出节点与边的统一地址，邻接关系由 2-2 的邻接算法提供。
4. **前馈块的“先验”可以是三类**：GNSS 位置、卫星图（第 6 类）、相邻块的重叠结果。前两类给绝对位置，第三类给相对一致性，三者组合更合理。

## 8. 坐标系与大范围数值问题的做法

本节说明大范围场景里坐标系与数值精度的做法。其中 3D Tiles 与 CESIUM_RTC 有一手规范可查 [^30][^31]，其余为按公式的推算或通行做法，已逐项标明。

### 8.1 为什么大坐标会出问题（推算，已用代码核对）

- **浮点间隔**：单精度浮点的相邻可表示数之间的间隔随数值增大。ECEF 坐标约 $6.4\times10^6$ m，单精度间隔为 0.5 m；距离 $10^5$ m 的坐标间隔约 7.8 mm，$10^3$ m 约 0.06 mm；双精度在 $6.4\times10^6$ m 处的间隔约 $9\times10^{-10}$ m。（用 numpy 的 `spacing` 核对。）
- **地球曲率**：切平面近似下，距原点 $d$ 处地表偏离切平面约 $d^2/(2R)$（$R=6371$ km）：244 m 约 0.5 cm，1 km 约 7.8 cm，10 km 约 7.8 m，100 km 约 785 m。
- **含义**：一块几百米的场景里，局部系近似足够；数值精度的问题出现在“全局坐标直接进入单精度计算”时；曲率误差在十公里量级才显著。

### 8.2 三种通行做法

| 做法 | 要点 | 出处与状态 |
| --- | --- | --- |
| 双精度全局、单精度局部 | 全局坐标用双精度（ECEF 或大地坐标）存放，计算前减去一个原点，转成单精度的局部量 | 通行做法；MASt3R-Fusion 的状态全用 float64 [^27]；GeoRay 的 RPC 定位在 CPU 上用 float64 算（见 8-1） |
| 相对中心渲染（RTC） | 顶点位置存成相对一个“中心”的量，使 32 位浮点足以描述顶点到中心的距离；运行时用修改过的模型视图矩阵使中心相对眼睛，避免在 GPU 上做大平移的 32 位减法 | CESIUM_RTC 扩展的 README 明确描述了这一技术，并指出中心可以是“虚拟地球应用中的 WGS84 坐标，或空间数据结构中包含该模型的节点的原点” [^31] |
| 分块局部系 | 每块取各自的局部坐标系（如东北天），块间以变换连接 | 通行做法；第 3 类的大场景方法各自约定局部系 |

### 8.3 3D Tiles：把大场景按空间层次组织的开放标准 [^30]

3D Tiles 是用于流式传输海量异构三维地理空间数据的开放标准，其规范对本板块有几条直接相关的规定（均据规范主分支的文本核对）：

- **坐标系**：使用右手笛卡尔坐标系，局部系以 $z$ 轴向上；一个瓦片集的全局坐标系“通常是 WGS 84 的地心地固系（EPSG 4978），但不必如此”，例如发电厂可以完全在其局部坐标系里定义；瓦片集的 CRS 可在元数据里显式给出；每个瓦片可带一个变换矩阵，把自己的局部系变换到父瓦片的坐标系。
- **区域包围体**：`region` 以 `[西, 南, 东, 北, 最小高度, 最大高度]` 表示，经纬度在 WGS 84 基准、取 EPSG 4979 但**单位用弧度**，高度是相对 WGS 84 椭球的米；瓦片变换不作用于 `region`。
- **隐式分块**：瓦片可按四叉树（只在 $x$、$y$ 方向减半，子瓦片 4 个）或八叉树（三个维度都减半，子瓦片 8 个）递归细分；对 `region` 包围体，$x$、$y$、$z$ 分别对应经度、纬度与高度；同一层的瓦片按 **Morton Z 序** 排列并用可用性位流记录；球形包围体不可用于细分；另有 S2 包围体的扩展。
- **与本板块的关系（本文归纳）**：3D Tiles 的区域四叉树或八叉树与 Z 序，与 GeoSOT 的经纬度加高度域剖分、四叉树与 Z 序在结构上非常接近；这说明“用经纬度四叉或八叉的网格组织三维大场景”不是新想法，而是已有的工程标准。8-3 把重建结果落到 DGGS 时，应把 3D Tiles 作为互操作对象与对照。两者的差别（本文判断，待核对）：3D Tiles 的细分以包围体的几何中点为准，不涉及 GeoSOT 的 64′、64″ 扩展与标准化编码，也不提供全局唯一的单元标识；这些是否构成优势，需在 8-3 中论证。

### 8.4 小结

- 精度问题有成熟的工程解法（双精度全局加局部量、相对中心渲染、分块局部系），并已被 3D Tiles 与 CESIUM_RTC 固化；所以 DGGS 不能把“解决浮点精度”当作新贡献，只能作为“一套带全局地址与层级的局部系约定”。
- 3D Tiles 已给出“经纬度加高度的四叉树或八叉树加 Z 序”的开放做法，8-3 须与之对照。
- 本板块的研究价值更可能在“前馈块之间的一致性与拼接”，而非数值精度本身。

## 9. 小结：各类方法在“世界系、范围、拼接”上的能力

| 类别 | 世界系输出 | 大范围 | 块间拼接 | 备注 |
| --- | --- | --- | --- | --- |
| 1 SfM 加 MVS | 须另行配准 | 可，但慢 | 通过全局束调整 | 局部系的来源 |
| 2 神经场与高斯 | 否，局部系 | 否 | — | 逐场景优化 |
| 3 大场景分块方法 | 否，局部系 | 是（分块） | 各自设计 | 与 8-1 最相近 |
| 4 前馈式重建 | 否，参考相机系 | 否，少视图 | — | 需外部先验 |
| 5 卫星摄影测量与 RPC | 是，大地坐标 | 小窗口 | 未实现 | GeoRay |
| 6 前馈地理视图合成与生成 | 部分（局部系加 GPS） | 否，小块 | 未讨论 | 空白所在 |
| 7 外部先验 | 取决于 GNSS | — | — | 精度上限 |

DGGS 可能的切入点：块划分与坐标约定（单元即块，局部系以单元中心为原点，尺度由层级给出）、块边界与重叠带的统一定义、块间偏移的校正、结果按编码落地与检索。这些都只作用于表示与组织，不改变位姿与尺度估计的精度。
