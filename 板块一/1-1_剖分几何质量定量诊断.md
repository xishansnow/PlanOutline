# 1-1 轴对齐剖分网格的适用性评估：特性画像、适用域与选型依据

所属：板块一 · 轴对齐剖分网格的适用性评估与演进 ｜ 返回总览：[PlanOutline.md](../PlanOutline.md)

## 1. 定位

本文是板块一的起点。基本立场是：**没有最好的 DGGS，只有最适用的 DGGS**。网格的每一项特性在某些需求下是代价，在另一些需求下是优势，诊断缺陷本身不是目的；目的是弄清“什么需求适合什么网格”，并给出可检验的依据。

研究对象不限于 GeoSOT，而是一整类网格：**轴对齐剖分网格**，即网格边界沿某一对坐标轴方向、按层级逐级细分的离散全球网格。GeoSOT、Geohash、OGC 的 WorldCRS84Quad 瓦片矩阵集、GNOSIS Global Grid、北斗网格位置码、WebMercatorQuad 与 Open Location Code 都属于经纬度上的轴对齐剖分；OGC Topic 21 第二版的修订内容包括把核心规范扩展到支持轴对齐单元，轴对齐 DGGS 的专门部分（第 4 部分）则列为后续计划 [^1]；OGC API – DGGS 的 DGGRS 定义已用 `cellAxisAligned` 约束描述这类网格 [^8]。

把研究对象从单一网格提升为一类网格有三点好处：

1. 结论更普适：多数特性来自“在经纬度上轴对齐”这一共同选择，而不是某个网格的设计失误。把共性特性与个性特性分开，评估才有解释力。
2. 立论更稳妥：GeoSOT 以这类网格的代表实例出现，其扩展剖分、度分秒整除等设计被放在同类方案中横向比较，既说明在哪些需求下它是最适用的，也说明在哪些需求下需要补充什么，不会写成对单一标准的批评。
3. 衔接国际标准：与 OGC 对轴对齐 DGGRS 的支持直接对话，为 GeoSOT 注册为 DGGRS 提供分析框架。

本文要回答的核心问题是：**给定应用的需求，哪些轴对齐网格适用，适用域的边界在哪里，指标能否预测任务中的实际表现**。三步展开：以应用画像刻画需求，以指标刻画网格的特性（优势与代价并重），再由需求推出适用域并以任务实验检验。结论决定 1-2 至 1-5 的优先级（它们是在扩展适用域），也为板块二至七提供设计约束。宜最先推进。

## 2. 概念界定与分类框架

### 2.1 轴对齐的定义

**定义（轴对齐剖分网格）**。设 $T$ 是从地球表面（球面或椭球面）到平面的分片可逆映射，$(u,v)=T(\lambda,\varphi)$。若多层网格 $\mathcal{G}=\{\mathcal{G}_0,\mathcal{G}_1,\dots\}$ 满足下列三条，则称 $\mathcal{G}$ 为关于 $T$ 的轴对齐剖分网格，$T$ 称为对齐变换：

1. 单元为矩形：每个单元 $z\in\mathcal{G}_l$ 是 $(u,v)$ 平面中轴平行矩形 $[u_0,u_1]\times[v_0,v_1]$ 在 $T^{-1}$ 下的像，单元边界由 $u=\text{常数}$ 或 $v=\text{常数}$ 的坐标线构成；
2. 同层不重叠：同一层的单元互不重叠，并覆盖有效域；
3. 沿轴嵌套：$\mathcal{G}_{l+1}$ 的每个单元是 $\mathcal{G}_l$ 中某个单元沿 $u$ 轴、$v$ 轴方向切分所得的矩形。不要求各轴等分，也不要求同层各单元的切分方式相同。

第 3 条的宽松表述是有意的：Geohash 逐层交替二分经度与纬度，GNOSIS 在极区行只沿纬度方向切分而不沿经度方向切分（见 2.4），二者都应属于轴对齐网格。

按单元边界的性质，分为狭义与广义：

| 范围 | 判据 | 对 $T$ 的要求 | 代表 |
| --- | --- | --- | --- |
| 狭义（本文主要对象） | 所有单元的边界都落在经线与纬线上 | 不限定，凡 $u=f(\lambda)$、$v=g(\varphi)$ 且 $f$、$g$ 单调的可分离变换均可，取恒等变换（等距圆柱）即得经纬度矩形 | GeoSOT、Geohash、WorldCRS84Quad、GNOSIS Global Grid、北斗网格位置码、WebMercatorQuad（纬线间距按墨卡托）、Open Location Code |
| 广义（对照对象） | 存在 $T$ 使单元为轴平行矩形，但边界不全是经线与纬线 | 其他分片变换：等积变换，或把球面分成若干块、在各块自己的平面坐标中剖分 | HEALPix（各基本单元内的局部坐标）、S2（立方体面上经非线性校正的坐标）；rHEALPix、ISEA4R 等 |
| 非轴对齐（外部参照） | 不存在使单元成为轴平行矩形的 $T$ | — | H3、ISEA3H |

判别时只需问两个问题：存在 $T$ 使单元成为轴平行矩形吗？若存在，单元边界是否全部落在经线与纬线上？前者否则为非轴对齐，后者是则为狭义，否则为广义。

狭义的判据只看单元在地球上的边界，与 `crs` 无关，因此也不随投影而变：在等距圆柱、Web Mercator、Lambert 圆柱等积等可分离的圆柱投影中，经线与纬线都是垂直线与水平线，狭义网格在这些坐标系中均保持轴对齐，只是单元的大小与比例随投影变化。在横轴墨卡托（UTM）、圆锥投影、极射赤面等经纬线为曲线的投影中，同一网格不再轴对齐。相反，OGC 的 `cellAxisAligned` 是相对于 `crs` 的约束，同一网格换一个 `crs` 可能成立也可能不成立。上述对各投影的判断由经纬线在平面中的形状直接推出，未逐一对照投影的官方定义。

几点说明：

- 轴对齐只规定单元在某个平面中的形状与嵌套方式，不意味着单元边界是大圆弧，也不意味着单元边长相等。纬线不是大圆，狭义网格的单元只是经纬度意义下的矩形。
- 狭义网格的边界取自经纬线，使其可与经纬度栅格数据精确对齐，也使面积与形状缺陷由同一个函数 $\cos\varphi$ 决定（4.2）；广义网格通过改变 $T$ 改变这些缺陷。
- 与 OGC 的关系（已对照原文）：Topic 21 把 `cellAxisAligned` 定义为单元边平行于基准 CRS 的坐标轴 [^1]；OGC API – DGGS 的 DGGRS 定义写为所有单元几何的所有边都与 `crs` 的某一坐标轴对齐 [^8]。本文第 1 条即此约束，只是把“基准 CRS”推广为对齐变换 $T$ 的像平面；第 2、3 条对应 OGC 另行规定的 DGGH 性质（`nestedChildCell` 与 `refinementRatio`），不属于 `cellAxisAligned` 本身，是本文为讨论层级嵌套而增加的要求。因此本定义比 OGC 的约束更严，不与之冲突。
- OGC 的实例与本文分类一致：GNOSIS 的 `crs` 为 EPSG:4326，对应狭义；HEALPix 的单元边与旋转 45° 后的投影坐标轴对齐，ISEA9R 与 IVEA9R 需先把 ISEA 平面旋转、剪切并缩放，对应广义 [^8]。S2 与 ISEA4R 不在 OGC 的 DGGRS 定义之列，其归类按本文定义判断。Topic 21 把轴对齐 DGGS 的专门部分（第 4 部分）列为后续计划 [^1]，目前尚无独立的轴对齐标准文本。DGGAL 把 HEALPix、rHEALPix、ISEA4R 也称为轴对齐 [^2]。
- 由此可把轴对齐网格统一写成“对齐变换 + 平面上的沿轴嵌套剖分”，两者分别决定不同的缺陷来源。六边形网格不属于轴对齐网格，作为外部参照。

### 2.2 设计参数

任一轴对齐剖分网格由以下参数刻画，缺陷可逐一归因到参数上：

| 参数 | 含义 | 不同网格的取值示例 |
| --- | --- | --- |
| 坐标变换 $T$ | 剖分在哪个平面上进行 | 经纬度恒等变换（GeoSOT、Geohash）；等积变换（HEALPix）；立方体投影加非线性校正（S2） |
| 根区域 | 第 0 层覆盖的范围与单元数 | GeoSOT 扩展为 512°×512° 的单一根 [^3]；WorldCRS84Quad 第 0 层为东西两个 180°×180° 瓦片；GNOSIS Global Grid 第 0 层为 4×2 个 90°×90° 瓦片 [^8][^9]；HEALPix 为 12 个基本单元 |
| 各轴细分比 | 每层每个轴分几份 | 四叉（2×2）；GNOSIS 细化比为 4，但极区行不沿经度方向分裂（见 2.4）；Geohash 交替二分经度与纬度；北斗网格位置码按图幅分级的混合进制 |
| 整数对齐 | 是否在度、分、秒处对齐 | GeoSOT 以 64′、64″ 扩展实现度分秒整除；Geohash、WorldCRS84Quad 与 GNOSIS 为纯二进制 |
| 极区处理 | 高纬度是否特殊处理 | GNOSIS 通过逐行合并经度方向的列，使任一层级仅 4 个单元触及极点 [^8]；北斗网格位置码常规剖分只覆盖 88° 以内；GeoSOT 与 Geohash 不作处理 |
| 编码顺序 | 单元编号在一维上的排列 | Z 序（GeoSOT、Geohash）；GNOSIS 为逐行扫描（行优先、自左向右、自上而下）[^8]；Hilbert（S2）；嵌套编号（HEALPix） |

北斗网格位置码的参数据二手来源（技术博客对 GB/T 39409-2020 的转述，标准原文未获取）：适用于南纬 88° 至北纬 88°，二维划分十级；第 1 级为 6°×4°（经度带 01 至 60，纬度带 A 至 V 共 22 个，22×4°=88°，与 88° 范围吻合），第 2 级 12×8（30′×30′），第 3 级 2×3（15′×10′，对应 1:5 万图幅），第 4 级 15×10（1′×1′），第 5 级 15×15（约 4″），第 6 级 2×2，第 7 级 8×8，第 8 至 10 级各 8×8；码元最多 20 个，分十一段。可见其为混合进制，不是 2 的幂次剖分。GNOSIS Global Grid 的参数见 2.4。

### 2.3 共性特性与个性特性

每项特性归因到设计参数，并分别标出它在什么需求下是代价、在什么需求下是优势。

| 特性 | 归因参数 | 性质 | 代价出现的需求 | 优势出现的需求 |
| --- | --- | --- | --- | --- |
| 面积随纬度按余弦收缩 | 经纬度恒等变换 | 狭义轴对齐网格的共性 | 全国与全球尺度的统计须面积加权 | 区域尺度内几乎无影响（4.6.1）；单元边界与经纬度格网一致 |
| 高纬度网格狭长 | 经纬度恒等变换 | 共性 | 高纬度应用 | 低纬度近似方形，中国大陆最北端长宽比约 1.7 |
| 两极奇异、近极网格退化 | 经纬度恒等变换、极区处理 | 共性，可由极区处理缓解（GNOSIS 以变宽行使每极仅 4 个单元，见 2.4） | 全球连续计算 | 应用范围在 88° 以内时不涉及 |
| 跨粗层级边界的边界问题 | 层级四叉结构本身 | 所有层级网格的共性，与是否轴对齐无关 | 有范围对象的表达 | 点对象与层级前缀查询不受影响 |
| 无效编码空间 | 根区域、整数对齐 | GeoSOT 等扩展根区域设计的个性 | 以编码为稠密数组下标 | 键值存储不受影响；换得度、分、秒的整数层级 |
| 层级过渡处尺寸不一致、部分有效网格 | 整数对齐 | GeoSOT 度分秒整除设计的个性 | 需要同层单元等价的统计与误差分析 | 与度分秒表示的经纬度数据与图幅整数对齐 |
| 单元长宽比在层级间交替变化 | 各轴细分比 | Geohash 等交替二分设计的个性 | 要求尺寸随层级稳定的应用 | 逐位交替，编码简单 |
| Z 序局部性一般 | 编码顺序 | 可替换的设计选择 | 大窗口范围查询 | 前缀包含关系直接对应层级包含 |

优势栏是设计意图，量化见 4.1 的指标 9 等。这张表本身就是本文的一个主要论点：GeoSOT 被批评的特性中，面积、形状与极区问题是所有经纬度轴对齐网格共有的，代价换来的是与经纬度格网数据精确对齐；无效编码与层级过渡问题才是 GeoSOT 的设计代价，换来的是度、分、秒的整数层级。同一特性在不同需求下的利弊不同，所以不存在脱离需求的最优网格。代价的缓解路径也不同：前者通过派生视图与极区方案（1-3、1-4），后者通过规范化处理（1-5）。

### 2.4 GNOSIS Global Grid 的参数

GNOSIS Global Grid 是 OGC API – DGGS 附录 B.10 中定义的 DGGRS，基于同名的变宽二维瓦片矩阵集 [^8][^9]。以下参数来自这两份官方文本，推断之处单独标注：

| 项目 | 取值 |
| --- | --- |
| 坐标参考系 | EPSG:4326（WGS84 经纬度），原生坐标即经纬度，数据导入导出无需重投影 |
| 单元类型与对齐 | 矩形，`cellAxisAligned` 为真；`basePolyhedron` 在定义中填为八面体，属名义取值，实际剖分在经纬度平面进行（对“八面体”一词的理解为推断） |
| 细化比与策略 | 4，嵌套子单元 |
| 第 0 层 | 瓦片矩阵 4 列×2 行，每个瓦片 256×256 单元，单元边长 0.3515625°（即 90°/256），原点 (90°N, 180°W) |
| 极区处理 | 第 $L$ 层的瓦片矩阵为 $2^{L+2}$ 列×$2^{L+1}$ 行；北半球第 0 行沿经度方向合并 $2^L$ 列，第 $k$ 个二进制纬度带（行号 $2^{k-1}$ 至 $2^k-1$，$k=1,\dots,L-1$）合并 $2^{L-k}$ 列，南半球对称；纬度 45° 以内不合并。因此任一层级仅 4 个单元触及每个极点（对 29 个层级的 JSON 逐层核对，与此闭式一致） |
| 单元总数 | $(16\cdot4^L+8)/3$：第 0 层 8 个，第 1 层 24 个，第 2 层 88 个，第 3 层 344 个（由上述合并规律推导，并对 29 层逐层核对） |
| 面积偏差 | OGC 文本给出至第 25 层相对平均面积约 −25.8%/+66.0%（相对中位数 ±45.9%）；DGGAL 文档给出相对中位数最大偏差约 48%。按椭球等积纬度逐行复算：第 25 层平均单元 849.4 cm²，相对平均值 −25.79%/+65.97%，与 OGC 一致；OGC 的 ±45.9% 等于相对平均值的半极差 $(0.6597+0.2579)/2$，相对中位数的半极差约 46.3%；DGGAL 的约 48% 未能复现，口径不明。DGGAL 软件自身给出的第 2 至 8 层单元面积与本文复算一致，其文档中的约 48% 在这些层级及无穷层极限下都不出现，视为口径或版本不明。OGC 文本明确指出其误差超过 1%，不满足等积要求，但同一纬度行内偏差相同，可按行计算并加以补偿 |
| 单元标识 | 文本形式为“层级-行-列”三个十六进制数，以连字符分隔；64 位整数形式为低 30 位列、其后 29 位行、高 5 位层级 |
| 子单元顺序 | 逐行扫描，行优先、自左向右、自上而下 |
| 最大层级 | 瓦片矩阵集示例列到第 28 层（共 29 层）；OGC 文本的面积估计列到第 25 层（平均单元约 849 cm²，复算为 849.4 cm²） |
| 单元与瓦片的对应 | DGGRS 的单元即同层瓦片矩阵集的瓦片（每瓦片含 256×256 个单元格）：以此计数与面积复算得到的第 25 层平均单元面积与 OGC 的 849 cm² 一致，DGGAL 默认深度 8 对应 65536（=256×256）个子单元也与之吻合 |

对比时需注意：GNOSIS 与 GeoSOT 同属狭义轴对齐，但用“变宽行”换取近似等面积，代价是同一层级内不同纬度行的经度向列数不同，邻接与行列索引的计算比规则网格复杂。`basePolyhedron` 填为八面体，与第 0 层 8 个单元（每极 4 个）的结构一致，可理解为八面体的 8 个面（推断，OGC 文本未加说明）。DGGAL 约 48% 的口径仍不明。

## 3. 研究问题

1. 如何以应用画像刻画需求？画像的哪些维度决定网格的适用性？
2. 如何为轴对齐剖分网格建立一套覆盖几何、编码与任务三个层面的质量指标，并能延伸到非轴对齐网格作为参照？如何把每项特性归因到设计参数，区分共性与个性？
3. 如何由需求推出每个网格的适用域？按指标预测的适用性排序，与下游任务中的实际排序是否一致？

关键问题：指标能否预测任务中的适用性排序，以及特性如何归因到设计参数。

## 4. 研究内容

### 4.1 质量指标体系

指标按六个要素组织（网格几何性质的比较框架见 [^6][^7]）：单元几何、邻接拓扑、层级结构、编码与键空间、对象表达、数据对齐与互操作。分核心与次要两档：核心档共 10 项，直接对应下游任务损失，进入 4.5 的任务实验；次要档只在几何对比中计算，不进入任务实验。

#### 4.1.1 统一口径

1. 特征尺度：不同网格的单元形状不同，以等效边长 $s=\sqrt{A}$（单元面积的平方根）作为单元尺度，对比时按 $s$ 配对，不按层级编号配对。
2. 球面与椭球：所有几何指标分别按球面与椭球计算，二者之差本身作为结论报告。球面上经纬矩形面积 $A=R^2\Delta\lambda(\sin\varphi_2-\sin\varphi_1)$，椭球上以等积纬度代入。
3. 按单元与按面积加权：同一指标分别按单元计数与按地表面积加权统计。高纬度单元小而多，按单元计数会使极区偏差占主导，按面积加权才对应实际应用。
4. 偏差口径：面积偏差同时报告相对平均值与相对中位数两种统计。OGC 与 DGGAL 对 GNOSIS 的面积偏差各用一种口径，数值不同（见 2.4），引用时须注明。
5. 实现相关的指标：编码、解码与邻居查询的吞吐等只作次要指标，须控制实现语言与优化水平，不把实现差异归因于网格。

#### 4.1.2 核心档（10 项）

| 要素 | 指标 | 定义与计算方式 | 主要关联场景 |
| --- | --- | --- | --- |
| 单元几何 | 1. 面积变异 | 同层面积的变异系数 $\mathrm{CV}=\sigma_A/\mu_A$ 与极差比 $A_{\max}/A_{\min}$；分别按单元与按面积加权，并报告两种偏差口径 | 全球气候（未加权统计偏差）、低空（容量） |
| 单元几何 | 2. 长宽比与紧致度 | 长宽比 $\rho=d_{EW}/d_{NS}$，以单元中点处大地线长度计算；球面等周商 $\mathrm{IPQ}_s=(4\pi A-A^2/R^2)/P^2$，取值不超过 1（球面等周不等式，$P$ 为周长） | 低空（安全间隔）、气候（图消息传递） |
| 单元几何 | 3. 近极最小边长 | 近极各层单元最小边长与同层名义边长之比，以及触及极点的单元数 | 全球气候 |
| 邻接拓扑 | 4. 邻接距离一致性 | 对每个单元，4 邻域与 8 邻域邻居中心距离的变异系数，以及最远与最近邻居的距离比 | 全球气候（2-4）、低空（5-1） |
| 层级结构 | 5. 配对尺寸误差 | 给定目标 $s$ 序列（如 10 m 至 100 km），各网格取与之最接近的层级，误差为 $\ln(\bar s_l/s)$，报告最大绝对值；$\bar s_l$ 取该层级单元 $s$ 的面积加权中位数 | 全部（对比公平性） |
| 编码与键空间 | 6. 有效编码比例 | 有效单元数占该层编码空间的比例 | 城市大数据（稠密数组、索引） |
| 编码与键空间 | 7. 部分有效单元比例 | 按剖分规则逐层枚举，部分有效单元占该层单元的比例 | 低空、城市大数据 |
| 对象表达 | 8. 覆盖成本曲线 | 对象 $O$ 在单元数预算 $K$ 下的最小冗余面积比 $\eta(K)=\min_{\lvert C\rvert\le K}A(\cup C)/A_O$，分单层与多层混合两个变体；$K=1$ 即最小包围单元，对应 4.4 的解析模型。对象取建筑轮廓、禁飞区、航迹段、行政区，用贪心法求解 | 低空（虚警）、城市大数据（候选冗余） |
| 数据对齐 | 9. 栅格对齐度 | 对给定分辨率的经纬度栅格（如 ERA5 的 0.25°、DEM 的 1″ 与 3″），统计满足下列条件的层级：层级单元恰为若干完整像元之并，或像元恰为若干完整单元之并；并统计各层级被单元边界切分的像元比例 | 全球气候（ERA5）、城市大数据 |
| 局部性 | 10. 聚簇指标 | 查询窗口所需连续编码区间数与聚簇数，与 2-5 共用 | 城市大数据 |

指标 8 的 $K=1$ 特例给出现有最小包围单元的表现，作为 1-2 扩展单元的基线；指标 9 量化狭义网格与经纬度栅格精确对齐这一优势，使评估矩阵同时包含缺陷与优势。

### 4.2 共性特性的解析刻画

对狭义轴对齐网格，单元是经纬度矩形（以等距圆柱的恒等变换表示即可），面积与形状缺陷可以统一解析：同层单元面积约按 $\cos\varphi$ 收缩，纬度 88° 处约为赤道的 3.5%，即相差约 29 倍；东西向边长同样按 $\cos\varphi$ 收缩，长宽比按 $1/\cos\varphi$ 增大。这些结论与具体网格无关，对 GeoSOT、Geohash、WorldCRS84Quad 一律成立。

同一解析也说明缺陷的影响取决于尺度：一个跨纬度 1° 的城市（中心纬度 40°），区域内同层单元面积的相对变化约为 $\tan40^\circ\times\Delta\varphi\approx1.5\%$。面积畸变在全球尺度显著，在城市尺度几乎可以忽略。

广义轴对齐网格通过改变坐标变换 $T$ 消除或减轻这类缺陷：HEALPix 以等积变换获得严格等面积 [^4]，S2 以非线性校正减小面积差异。把 $T$ 作为唯一变量做对比，可以定量说明“换一个变换能换来什么、要付出什么”，这正是 1-3 等面积派生视图的理论依据：1-3 的等积纬度派生网格，本质上就是在 $(\lambda,\sin\varphi)$ 平面上的轴对齐剖分。

### 4.3 个性特性的逐网格刻画

以 GeoSOT 为重点案例，依据剖分提出者论文 [^3] 的定义推算：第 0 层是中心与原点（本初子午线与赤道的交点）重合的 512°×512° 网格，第 1 至 9 层逐层四分到 1°，第 10 至 15 层对 1° 扩展为 64′ 后的网格四分，第 16 至 21 层对 1′ 扩展为 64″ 后的网格四分，第 22 至 32 层逐层四分，共 32 层，最细层为厘米级（约 1.5 cm）；已对各层逐层枚举验证。GB/T 40087-2021 标准全文未能获取，与标准文本的一致性仍待核对：

- 度级层级上，有效经纬度域占扩展编码空间的比例为 $\dfrac{360\times180}{512\times512}\approx24.7\%$；度到分、分到秒的扩展各保留 $(60/64)^2\approx87.9\%$；到秒级时整体有效比例约为 $0.247\times0.879^2\approx19\%$。
- 部分有效网格出现在度级的第 0 至 7 层（90° 与 180° 不是这些层级单元边长的整数倍）、分级的第 10 至 12 层与秒级的第 16 至 18 层（详见 1-5）；第 8、9、13 至 15 层与第 19 层及以下不出现部分有效网格。

对 Geohash 刻画层级间长宽比的交替；对 WorldCRS84Quad 刻画双根结构对 180° 经线与编码的影响。

对 GNOSIS Global Grid，重点刻画变宽行换来的面积均衡程度及其代价：

- 面积：逐层统计单元面积相对平均值与中位数的偏差分布，与 OGC 文本给出的约 −25.8%/+66.0%（相对平均面积，至第 25 层）及 DGGAL 给出的约 48%（相对中位数）互相校验；本文已复算椭球上第 25 层的 −25.79%/+65.97%，与 OGC 一致，DGGAL 的数值尚待复现，并给出偏差随纬度行的分布。偏差在同一纬度行内相同，因此可按行预先计算面积权重，作为补偿手段的一部分（4.6.2）。
- 形状：合并经度方向的列后，高纬度单元的东西向边长不再按 $\cos\varphi$ 一路收缩，应与 GeoSOT 对比长宽比随纬度的变化。
- 代价：不同纬度行列数不同，邻接关系、行列索引与区域查询比规则四叉网格复杂；逐行扫描顺序的空间局部性与 Z 序对比（与 2-5 共用指标）。
- 对齐：GNOSIS 与 GeoSOT 同为经纬度轴对齐，可作为“同样经纬度对齐、极区处理不同”的最直接对照：GeoSOT 以度分秒整除换取整数对齐，GNOSIS 以变宽行换取近似等面积。

### 4.4 边界问题的解析模型

设对象外包矩形边长为 $s$，第 $l$ 层单元边长为 $d_l$。对象位置均匀随机时，其完整落入某一第 $l$ 层单元的概率约为 $\left(\max(0,\,1-s/d_l)\right)^2$。由此可推导最小包围单元层级的分布，以及包围单元面积与对象面积之比的期望与尾部概率。这一模型适用于所有四叉层级网格；GeoSOT 层级过渡处单元尺寸不一致（如 32′ 与 28′）、Geohash 长宽比交替时，需对模型分段修正。解析结果与真实对象（建筑轮廓、禁飞区、航迹段）上的实测分布对照，为 1-2 扩展单元提供改进空间的上界估计。

#### 4.5.3 任务验证

验证的目标是预测排序与任务实验排序是否一致，如以 Kendall τ 或前 $k$ 名一致度衡量（度量选取待定）。对每个画像下的代表任务，比较按指标预测的网格适用性排序与任务指标的实际排序；不一致之处指出哪项指标未覆盖任务损失，作为指标体系的改进依据。

每类场景选一到两个代表任务，度量各网格以及单参数对照网格上的任务指标。几何指标取自 4.1.2 的核心档（编号为指标序号），任务损失指标是下游任务的实际度量；实验要检验的是前者能否预测后者。

| 场景 | 代表任务 | 任务损失指标 | 对应的几何指标 | 重点考察的特性 |
| --- | --- | --- | --- | --- |
| 低空 | 基于网格的航迹冲突判定（2-1）、空域要素表达（5-1） | 虚警率、空域容量损失、存储量 | 8 覆盖成本曲线；2 长宽比与紧致度（以单元为单位定义的安全间隔）；7 部分有效单元比例（跨层级统计时的单元不等价） | 边界问题、形状畸变、层级过渡 |
| 全球气候 | 全球均值与区域统计、剖分图上的消息传递（2-4）、再分析场与网格间的数据转换 | 未加权统计偏差、节点度与面积分布、预报误差、重采样误差 | 1 面积变异；3 近极最小边长；4 邻接距离一致性；9 栅格对齐度 | 非等面积、两极奇异、邻接不均、数据对齐 |
| 城市大数据 | 时空范围查询、空间连接（7-3）、栅格数据落网 | 候选集冗余率、访问数据块数、延迟、稠密数组内存 | 8 覆盖成本曲线；6 有效编码比例；7 部分有效单元比例；10 聚簇指标；9 栅格对齐度 | 无效编码、编码顺序、边界问题、数据对齐 |

指标 5（配对尺寸误差）不对应某个场景，而是所有实验的控制变量：各网格按相近 $s$ 配对后才能比较任务指标，配对误差较大的网格对须在结果中注明。10 项指标在表中均有对应。

单参数对照网格用于把任务表现的差异归因到某个设计参数，每个参数对应的对照与隔离的指标如下：

| 设计参数 | 对照做法 | 隔离的指标 |
| --- | --- | --- |
| 坐标变换 | 狭义内：经纬度（GeoSOT、Geohash）换为 WebMercatorQuad，只变 $T$；跨类：换为 1-3 的等积纬度网格或 HEALPix | 1、2、3、4 |
| 极区处理 | WorldCRS84Quad 或 GeoSOT 换为 GNOSIS；再换为 1-4 的极冠方案 | 1、3 |
| 根区域与整数对齐 | GeoSOT 换为纯二进制经纬四叉（WorldCRS84Quad、Geohash） | 6、7、9 |
| 编码顺序 | 同一网格上 Z 序换为 Hilbert 类排序 | 10 |
| 对象表达方式 | 最小包围单元换为多单元覆盖，再换为 1-2 的扩展单元 | 8 |
| 邻接结构 | 四边形网格换为 H3 六边形（外部参照，只比较几何指标 4，不做任务实验） | 4 |

这样任务表现的差异可以分解到各个设计参数上，从而判断哪些代价是轴对齐的固有属性、哪些可以在保持轴对齐的前提下消除。

需要注意各参数并不严格正交。例如换为等积纬度网格会消除面积畸变，但高纬度单元的长宽比反而更大，指标 1 改善的同时指标 2 变差；极区处理的改变也会同时影响面积分布。因此每次对照都要同时报告受影响的全部指标，不能只报告预期改善的那一项，归因时以“改变参数后各指标的变化向量”为准。

### 4.6 适用域与选型：规避、补偿与改进

落脚点是为每项特性在需求不匹配时给出办法，使网格的适用域得以扩大。办法分三类，成本依次升高：

- 规避：限定使用场景，在代价不造成实质损失的范围内使用，并把范围写成定量的适用边界，即适用域本身。
- 补偿：网格不变，在计算层面修正，如面积加权、以真实球面距离代替网格距离。
- 改进：在网格层面修补，以附加层或派生视图实现，由 1-2 至 1-5 完成，对应适用域的扩展。

规避本身就是贡献：以公式与实验给出“在什么尺度、纬度、层级下可以放心使用”，比笼统地说“有缺陷”更有用，也让 GeoSOT 的应用论文能明确声明适用范围。下表与 4.6.2 中的“缺陷”一词指对某一类需求构成代价的特性。

#### 4.6.1 适用边界的解析估计

以下边界由狭义轴对齐网格的几何关系直接推出，正式结论以 4.5 的任务实验校验。

| 缺陷 | 判据 | 适用边界示例 |
| --- | --- | --- |
| 面积畸变（区域内） | 中心纬度 $\varphi_0$、纬度跨度 $\Delta\varphi$ 的区域内，同层面积相对变化约为 $\tan\varphi_0\cdot\Delta\varphi$ | 容许 5% 时：纬度 30° 处跨度不超过约 5°，40° 处约 3.4°，60° 处约 1.7°；容许 1% 时，40° 处约 0.7°。城市与多数省级区域可不做面积加权 |
| 面积畸变（跨区域） | 两地同层面积之比为 $\cos\varphi_1/\cos\varphi_2$ | 中国大陆南北（约 18°N 至 53.5°N）相差约 1.6 倍，全国尺度统计须加权 |
| 形状畸变 | 单元长宽比约为 $1/\cos\varphi$ | 长宽比不超过 1.5 对应纬度 48° 以内，不超过 2 对应 60° 以内；中国大陆最北端约为 1.7 |
| 两极奇异 | 应用范围是否进入高纬度 | 应用范围在 88° 以内（北斗网格位置码的常规剖分范围）即不涉及；中国境内与绝大多数低空、城市应用都在此范围内 |
| 层级过渡与部分有效单元 | 所用层级是否出现部分有效单元 | 按 [^3] 的定义推算，第 8、9 层（2°、1°）、第 13 至 15 层（4′ 至 1′）与第 19 层及以下（4″ 及更细）不出现部分有效单元，单元要么完全有效、要么完全无效；需要同层单元等价的统计与误差分析宜优先选用这些层级，避开第 10 至 12 层与第 16 至 18 层 |
| 无效编码 | 是否以编码作为稠密数组的下标 | 键值存储与稀疏索引中无效编码不占空间，基本无影响；稠密数组应改为按度单元分块的 60×60 局部数组 |

| 形状畸变 | 限于中低纬度 | 安全间隔、缓冲区、邻域半径按米而不是按单元个数定义；图神经网络边特征写入真实距离与方向（2-4） | 极区方案与派生视图（1-3、1-4） |
| 两极奇异 | 应用范围限于 88° 以内 | 极区单独以极地投影网格处理后再映射回来 | 极冠剖分与衔接规则（1-4） |
| 边界问题 | 点对象不受影响；有范围的对象不用单一最小包围单元表达 | 以对象尺寸相称层级的多单元覆盖表达：在单元边长不小于对象尺寸的层级上，任何对象最多覆盖 2×2 个单元 | 扩展单元，以单一存储键达到同样的面积上界（1-2） |
| 层级过渡 | 选用单元完整有效的层级，见 4.6.1 | 以有效几何与实际尺寸参与计算 | 有效性语义与层级规范（1-5） |
| 无效编码 | 采用稀疏存储 | 学习化索引与哈希按有效编码分布训练，跳过空洞 | 统一主码与有效性判定（1-5） |
| Z 序局部性 | 以点查询与层级前缀查询为主的应用影响小 | 大窗口查询拆分为多个连续编码区间再检索 | 独立的 Hilbert 类或学习化存储键（2-5、2-6） |
| 维度不协调 | 在一个系统内固定水平、高度、时间的层级配比 | 跨系统交换时按对应表转换 | 多维层级对应规则（1-5） |
| 编码形式多样 | 一个系统内只用一种主码 | 只在系统边界做转换 | 二进制统一主码（1-5） |

由此得到的总体判断是：对中国境内的低空与城市应用，面积、形状与极区三项共性缺陷大多可以规避或低成本补偿，真正需要改进的是边界问题、层级过渡与编码顺序；对全球气候与地球系统模式，共性缺陷无法规避，等面积派生视图与极区方案是必需的。这一判断将由 4.5 的任务实验检验，并决定 1-2 至 1-5 在不同板块中的优先级。

### 4.7 对比网格

对比网格分四层，按作用与工作量收敛，避免对象过多而失焦。

| 层次 | 网格 | 类别 | 工具 | 做什么 |
| --- | --- | --- | --- | --- |
| 全套 | GeoSOT | 狭义轴对齐，扩展根区域、度分秒整除 | 自研实现，以标准文本校验 | 几何、编码、边界与任务实验 |
| 全套 | Geohash | 狭义轴对齐，交替二分 | 开源实现 | 同上 |
| 全套 | WorldCRS84Quad | 狭义轴对齐，双根四叉 | OGC 二维瓦片矩阵集 [^5] | 同上 |
| 全套 | GNOSIS Global Grid | 狭义轴对齐，变宽行近似等面积，极区每极仅 4 个单元 | [DGGAL](https://github.com/ecere/dggal)；OGC 瓦片矩阵集定义 [^9] 作为独立校验 | 同上 |
| 全套 | 北斗网格位置码 | 狭义轴对齐，按图幅混合进制 | 依 GB/T 39409-2020 自研（参数见 2.2 节说明，标准原文待核对） | 同上 |
| 全套 | WebMercatorQuad | 狭义轴对齐，边界为经线与纬线，但纬线间距按墨卡托变换；只改变 $T$ 的狭义对照 | OGC 瓦片矩阵集定义 [^10] | 同上，并作为“只换坐标变换”实验的对照 |
| 全套 | Open Location Code（Plus Codes） | 狭义轴对齐，20 进制混合进制，末级改为 5×4 细分 | 依官方规范自研或用其开源实现 [^11] | 同上 |
| 几何对照 | HEALPix | 广义轴对齐，等面积，1-3 的等积参照 | [HEALPix](https://healpix.sourceforge.io) | 几何与编码指标 |
| 几何对照 | S2 | 广义轴对齐，立方体投影，Hilbert 排序，1-5 的排序参照 | [s2geometry](https://s2geometry.io) | 几何与编码指标，局部性（与 2-5 共用） |
| 外部参照 | H3 | 非轴对齐六边形 | [h3geo](https://h3geo.org) | 仅几何指标 |
| 扩展 | GARS、Maidenhead 定位系统、GEOREF、国家基本比例尺地形图分幅（GB/T 13989） | 狭义轴对齐，固定层级的分幅体系 | 按各自规范自研，参数见下 | 仅几何指标，不计入必需工作量 |
| 扩展 | rHEALPix、ISEA4R、ISEA3H | 广义轴对齐或六边形 | DGGAL、[DGGRID](https://github.com/sahrk/DGGRID) | 与几何对照、外部参照作用重复，经同一指标脚本接入即可 |

全套对比的 7 个网格都是狭义轴对齐，与 1-1 的研究对象一致；几何对照与外部参照只承担参照作用，不做任务实验。MGRS 的格线是 UTM 的东距与北距，边界不是经线与纬线，不属于狭义，不列入。

新增两个全套网格的参数：

| 网格 | 剖分参数 | 来源与核实状态 |
| --- | --- | --- |
| WebMercatorQuad | `crs` 为 EPSG:3857；第 0 层 1×1 个瓦片，每瓦片 256×256 单元，第 0 层单元边长 156543.033928041 m，第 1 层 2×2；原点 (−20037508.3427892, 20037508.3427892) m；每层细化比为 4 | OGC 瓦片矩阵集 JSON [^10]，已核对。纬度上限约 ±85.0511° 由瓦片矩阵集原点 20037508.3427892 m（=πR）反算（85.0511287798°），原文未直接给出 |
| Open Location Code | 字母表 `23456789CFGHJMPQRVWX`（20 个）；前 10 位为 5 步 20×20 细分（经纬交错，自纬度起），第 11 至 15 位为纬度 5 份、经度 4 份的细分；最长 15 位，10 位以内只有偶数长度有效；码长 2 位为 20°、4 位为 1°、6 位为 1/20°、8 位为 1/400°、10 位为 1/8000°（约 13.9 m）；纬度截断到 ±90°，经度归一到 ±180°，解码得西南角 | 官方规范 [^11]，已核对。相邻有效层级的细化比为 400，层级很稀疏，按相近尺寸配对层级时粒度较粗 |

## 5. 实验设计

- 数据：OpenStreetMap 建筑轮廓与道路；低空禁飞区与限制区（公开或仿真）；ADS-B 航迹（OpenSky）；ERA5 再分析场；城市出租车或共享单车轨迹。
- 规模：全球几何统计逐层全量计算；任务实验选取至少两个城市与一个全球场景。
- 可复现性：指标计算、单参数对照网格与对比脚本开源，公开所用数据与查询负载。

## 6. 预期成果

1. 应用画像框架：刻画需求的维度，及其到 4.1 指标阈值的映射。
2. 轴对齐剖分网格的设计参数框架、特性到参数的归因表（含代价与优势两栏），以及一套适用于轴对齐网格、并可延伸到非轴对齐网格的质量指标体系，与 2-5 的聚簇指标互补。
3. 适用域图与选型决策流程：按应用画像给出各网格的适用域，供各板块与应用层论文声明适用范围；并说明哪些结论由推导得出、哪些由实验验证。
4. 适用性预测的验证结果：指标预测的网格排序与任务实验排序的一致程度，以及指标未覆盖之处。
5. 作为 1-2 至 1-5 优先级依据的“特性 × 场景 × 表现”矩阵，区分共性特性与个性特性。
6. 开源的多网格对比工具、单参数对照网格与基准数据。
7. 期刊论文一篇，建议投 IJGIS 或 Cartography and Geographic Information Science。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 研究对象扩大后工作量增加 | 几何指标对各网格统一计算，任务实验只在 GeoSOT 与少数代表网格（如 Geohash、GNOSIS、WebMercatorQuad）上做全套，其余网格只做几何对比；扩展层不计入必需工作量 |
| “轴对齐”的口径与 OGC、DGGAL 的用法不完全一致 | 明确区分狭义与广义，并在文中给出定义 |
| 部分网格缺少权威定义或开源实现 | 北斗网格位置码按标准文本自研，GNOSIS Global Grid 以 DGGAL 实现为准，并公开实现 |
| 任务损失受模型与数据影响，难以归因 | 采用单参数对照网格逐项替换，控制其余变量 |
| “最适用”的判断带有主观性 | 以应用画像与指标阈值显式表达需求，用帕累托思路给出不被支配的网格集合，不输出唯一答案；阈值的选取与敏感性一并报告 |
| 指标预测与任务排序不一致 | 作为结果报告，并据此指出指标体系未覆盖的任务损失，不回避不一致 |
